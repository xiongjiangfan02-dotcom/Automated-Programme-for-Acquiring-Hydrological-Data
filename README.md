# 贵州毕节大型水库实时水情采集模块

本模块面向 MVP：采集水利部“全国水雨情信息网”的毕节市大型水库实时水情。它不代表毕节全部水文站，也不采集普通河道站、流量或雨量数据。

## 当前实现

- 从大型水库页面自动发现当前公开接口，也允许配置固定接口用于应急切换。
- 保存原始页面、原始 JSON、解码结果、质量检查和批次日志。
- 对官网动态字体做字形映射解码。任一必需字段未解码时阻断主表输出。
- 使用版本化大型水库白名单，优先按 `idNo`，其次按标准名或受控别名精确匹配。
- 将 `--`、空值和接口零值统一作为缺测，主表留空，原始值写入审计数据。
- 严格复制模板并保持 `Sheet1` 七列表头和顺序不变，可增加 `原始数据`、`采集日志`工作表。
- 上传端口仅定义边界，默认且强制关闭，不连接 Seafile。

## 已核实的模板与来源

只读检查的 `D:/生态/获取/格式.xlsx` 仅含 `Sheet1`，A1:G1 依次为：流域、行政区划、河名、库名、时间、库水位(米)、日变幅(米)。模板只有表头，单元格格式为 General，无隐藏列、合并单元格或公式。运行时再次验证结构；变化时停止，禁止自行调整字段。

官网页面通过 JavaScript POST 加载数据。已见响应字段为 `bsnm / addvnm / rvnm / stnm / tm / rz / rzRange / idNo`，业务状态为 `returncode=0`、记录位于 `result`。接口路径会变化，因此每次从页面发现，不固化已观察到的路径。已见完整时间包含年份；部分字符串带动态字体标签，不能当普通中文或数字直接解析。

`references/official_reservoir_roster_2026.xlsx` 是应急管理部公开的 2026 年全国大型及防汛重点中型水库防汛责任人名录，原始地址和行号记录于白名单。已核实毕节属地的夹岩水利枢纽、洪家渡、倒天河、象鼻岭。**这份名录含重点中型，不能据此断言每一个候选都是大型**；程序只接受官网大型水库页面返回的匹配记录。附廓条目暂禁用，待进一步复核。白名单不是全部水文站名录。

未绑定 `idNo` 时，必须同时满足已核实的受控库名和完整行政区划匹配。只显示贵州省时，使用官方名录证实库名属地；空行政区划只允许已人工绑定且名称一致的站号。严禁任意子串匹配或从站号前缀猜位置。更细行政区划必须添加经证实的完整别名，不自动推断。

## 安装与运行

本机已经建立 `.venv` 并安装依赖。首次在其他机器安装时，使用 Python 3.11+ 和 `setup.ps1`；验证版本见 `requirements.lock.txt`。

```powershell
.\setup.ps1
.\.venv\Scripts\python.exe -m bijie_hydro.cli --config config/default.json validate-template
.\run_once.ps1
```

需要复现既有响应时，应复制配置到独立回放配置文件，将输出、归档、状态和字体缓存路径指向独立目录，避免影响正式历史状态。接口覆盖地址是可选的，仅用于记录已核实的接口来源。回放不访问网络；带字体标签的响应需要对应缓存字体。

```powershell
.\.venv\Scripts\python.exe -m bijie_hydro.cli --config config/replay.json collect --input-json path/to/raw_response.json
```

`run_once.ps1` 支持 `-Config` 和 `-Python`，默认使用本项目 `.venv`。正式加入 Windows 任务计划程序前，应先连续人工核验至少 3 个采集日。此项目不自动注册系统定时任务。

## 上线前必须完成

1. 将官网实际显示的水库逐项与官方名录核对；站号未测得时保持空数组，绝不填入猜测值。只有人工核实名称、属地和站号后才能绑定 `id_nos`。
2. 确认真实官网动态字体与本机参考字体能完整匹配。本实现按分解后的字形轮廓匹配，并隔离每个字体版本；轮廓不匹配或映射不唯一时停止。模拟字体测试通过不能替代真实官网验证。
3. 根据试运行记录调整全国记录数量、时效和日变幅阈值。
4. 保留书面授权、官方名录证据、数据来源 URL 和采集时间。

## 输出和审计

成功批次输出到 `D:/生态/获取/成果/<报表日期>/`，名称为 `毕节市大型水库实时水情_<报表日期>_<批次编号>.xlsx`。报表日期为本次北京时间采集日，官网观测时间单独保留，不能把快照当全天观测数据。

每个批次的原始响应和日志保存在 `D:/生态/获取/归档/<批次日期>/<批次编号>/`：

- `source_page.html`、`raw_response.json`：原始来源。
- `font_*.ttf`、`decoded_records.json`、`parsed_records.json`：字体、解码和筛选结果。
- `reservoir_allowlist.json`、`template_validation.json`、`provenance.json`：处理证据、模板摘要、模板校验和、采集时间、时区、回放标识和处理版本。
- `selected_records.json`、`quality_checks.json`、`batch_log.json`：候选标准记录、检查结果、任务状态和错误。
- `manifest.json`：本批次文件大小和 SHA-256 校验和，可检查后续内容是否变化；这不是数字签名，不能替代访问控制。

下载前失败的批次只包含已形成的文件，不伪造原始响应。任务状态为成功、重复跳过、无匹配数据、待复核或失败。普通采集/校验失败不会生成成果；如果成果已经安全保存、随后状态文件写入失败，则保留已生成成果并在批次错误中说明，排查后再重跑。

成果采用临时文件保存、重读校验后改名。原模板永不写入，已存在的成果拒绝覆盖。`Sheet1` 保持原七列及原表头样式；新增两张审计表。日期采用 `yyyy-mm-dd hh:mm`，数值以四位小数四舍五入并使用 `0.####` 显示，原始完整精度保留在归档。主表缺测为空单元格；零值包括日变幅的 `0`，按用户约定视为缺测。

审计表保留全部全国响应记录及每条筛选原因，字符串强制写为文本，避免被 Excel 当公式执行。超长审计单元格会标注截断，完整值仍在原始 JSON；XML 不允许的控制字符仅在 Excel 中移除，不修改原始归档。

## 清洗与质量控制

优先使用官网完整年份。仅遇到 `MM-DD HH:MM` 时，以采集年份推定；明显跨年时回退一年并接受时效检查，推定策略记录到审计。所有观测和采集时间使用北京时间。`--`、空值、零值缺测；非数值、非有限数字、无法解析时间属于错误，不静默转成普通缺测。

全国记录数和必需字段结构/类型、UTF-8 解码、目标相关字体解码、目标时间时效均须通过。非目标省份的未解析字形会记录为警告，不阻断毕节结果；行政区划无法解码，或贵州、已绑定站号、受控库名记录存在未解析字段时仍然阻断。同站同时间相同记录可合并，有冲突则停止；每库仅保留最新观测。历史站点消失、时间回退、日变幅或历史水位变化超过阈值均转待复核，不发布为正常成果。不合理阈值只能在人工验证后调整。

来源正常但白名单没有匹配记录时，目标记录检查标记为“无数据”，批次状态为“无匹配数据”，不会生成空成果或清空历史状态。这只表明当前页面与当前名录没有匹配项，不证明毕节没有水文数据。网络错误、业务状态异常、结构或目标相关字体失败均为采集失败。缺失流域、河名、已绑定站号的区划或合法缺测数值会记警告并保留来源缺测事实。

系统锁阻止并发运行，状态文件以原子替换方式保存。相同观测时间及数据的快照跳过新成果，但保留新批次审计。历史状态损坏会停止，禁止静默重置或自动丢弃历史。

## 上传边界

`upload.py` 定义 `upload_file(file_path, metadata)`、`upload_records(records, metadata)` 和 `check_upload_status(task_id)`，禁用实现始终拒绝上传，采集流程不调用上传模块。

后续可由独立上传任务消费已成功的成果，上传状态单独存储。幂等键建议为目标资料库、目标路径和文件 SHA-256；失败重试采用有限次数退避，不影响采集归档。Seafile 的服务器地址、凭证、资料库 ID、目录、文件名、标签及权限需另行配置，凭证放入安全凭证存储，不写进 Excel、普通配置或日志。本阶段未实现 Seafile 网络调用，也未测试上传。

## 定时建议

MVP 每日一次，建议北京时间 09:10，读取当时官网当前快照并保留全部历史批次，不承诺提供当天每小时记录。任务计划程序使用当前 Windows 用户，工作目录为项目目录；程序选择 `C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe`，参数为 `-NoProfile -File "D:\生态\bijie_hydro_collector\run_once.ps1"`，不依赖系统 PATH。配置单实例，关闭对所有失败一律重试的设置。普通网络故障可由管理员或分类监控在 10 分钟后最多补跑两次；访问限制退出码 5 禁止短间隔自动补跑。无需管理员权限；不要覆盖单位的脚本执行策略。

单请求默认超时 15 秒、最多尝试两次，有指数退避；403、401 或其他访问拒绝不重试，429 直接停止并记录 `Retry-After`，由管理员确认下一次运行时机，不能用自动短间隔任务反复触发限制。仅请求当前来源域名，拒绝跨域跳转/接口覆盖，无验证码识别、代理池、登录绕过或访问控制规避。

退出码：0 成功或重复跳过；2 采集/质量/配置失败；3 前置本地文件错误；4 来源正常但无匹配数据；5 访问被拒绝或限流。默认提醒方式是错误输出与批次日志，可接入单位现有监控；未发送邮件或消息，未连接任何外部通知服务。新增站点、持续缺测、访问限制和异常水位应人工复核。公开来源不等于可以无限共享；对外提供数据须保留来源和采集时间，并遵守授权范围，不能承诺绝对不会泄露数据。
