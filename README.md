# 贵州省大型水库实时水情采集模块

当前版本：**0.3.0**，对应 Git 标签 `v0.3.0`。

本模块采集水利部“全国水雨情信息网”大型水库页面中行政区划属于贵州省的全部公开记录。筛选不依赖特定水库名称、站号或人工维护的水库白名单。模块不代表贵州全部水文站，也不采集普通河道站、流量、雨量或未出现在大型水库页面中的中小型水库。

## 当前实现

- 每次访问大型水库公开页面并自动发现同源数据接口，不固化可能变化的接口路径。
- 解码官网动态字体，保存原始页面、接口响应、字体、解析结果和批次日志。
- 仅根据官网行政区划字段筛选贵州记录。接受 `贵州`、`贵州省`，以及以 `贵州省` 开头的更细行政区划。
- 官网库名原样进入成果，不做白名单别名替换，不要求提前登记 `idNo`。
- `--`、空值和接口数值零统一作为缺测；非数值和非有限数字仍按错误处理。
- 保持模板 `Sheet1` 七列表头和字段顺序不变，成果增加 `原始数据`、`采集日志`工作表。
- 上传接口保持禁用，不连接 Seafile 或其他外部存储。

## 数据范围

数据源页面为 `http://xxfb.mwr.cn/sq_dxsk.html`。页面通过 JavaScript POST 加载全国大型水库实时水情，已确认字段包括：

| 官网字段 | 成果字段 |
| --- | --- |
| `bsnm` | 流域 |
| `addvnm` | 行政区划，同时用于贵州筛选 |
| `rvnm` | 河名 |
| `stnm` | 库名 |
| `tm` | 时间 |
| `rz` | 库水位(米) |
| `rzRange` | 日变幅(米) |
| `idNo` | 内部去重和审计标识，不写入 `Sheet1` |

筛选规则不使用任意包含判断。`云南省贵州村`不会被误判；`贵州省毕节市`等以完整省名开头的细分区划会被纳入。行政区划为空或无法解码时，系统不能可靠判断省份，因此停止或排除输出，不根据水库名和站号猜测属地。

当前 MVP 只覆盖官网“大型水库”页面。官网未显示的贵州水库不会由本模块补齐，不能把成果理解为贵州所有类型水库名录。

## Excel 模板

模板路径为 `D:/生态/获取/格式.xlsx`。模板只读使用，程序不会覆盖它。运行时要求：

- 仅有 `Sheet1`。
- 第一行依次为：流域、行政区划、河名、库名、时间、库水位(米)、日变幅(米)。
- 仅七列和一行表头，无合并单元格、公式或额外工作表。

成果中的日期格式为 `yyyy-mm-dd hh:mm`，水位和日变幅使用 `0.####`，最多显示四位小数。主表缺测写为空单元格，原始值和缺测原因保留在审计数据及批次归档中。

## 安装与运行

运行环境要求 Python 3.11 或更高版本。项目已提供 PowerShell 脚本：

```powershell
.\setup.ps1
.\.venv\Scripts\python.exe -m bijie_hydro.cli --config config/default.json validate-template
.\run_once.ps1
```

`run_once.ps1` 默认使用项目 `.venv`，也可通过 `-Config` 和 `-Python` 指定其他配置或解释器。

### 图形化修改配置

运行下面的命令打开配置窗口：

```powershell
.\config_window.ps1
```

也可以直接双击项目目录中的 `open_config_window.cmd` 打开窗口。

窗口可以修改：

- 起始执行时间，例如 `09:00`（北京时间）；
- 每天采集次数（范围 1..24），窗口实时预览全部执行时刻；
- 单个网络请求最多尝试次数（含首次请求，范围 1..3，与每天采集次数分别设置）；
- 成果 Excel 存储位置；
- 原始数据和日志归档位置；
- Excel 模板文件位置。

每天采集次数表示按24小时均匀分配的计划次数。例如起始 `09:00`、每天2次，执行时刻为 `09:00` 和 `21:00`；每天3次为 `09:00`、`17:00` 和次日 `01:00`，每天循环。不能整除24小时的次数按分钟向下取整，间隔最多相差1分钟。这是计划触发次数；断网、关机、重复快照跳过等情况会影响实际成功次数和新增成果数量。默认仍每天1次。提高次数将增加官网请求量及本地归档量。

“保存配置”只保存并校验配置；“保存并更新任务”会在保存后重新注册 Windows 定时任务，使新的执行时间和每天次数生效。保存前先在同目录候选配置上校验全部配置和模板，通过后原子替换配置并生成 `config/default.json.bak`（上一次配置，后续保存会覆盖该备份）。校验失败时原配置保持不变。若其他窗口已经修改配置，需要重新打开本窗口。任务更新失败时会提示配置已保存，并展示错误详情；应查看任务状态后重试“保存并更新任务”。窗口不会修改模板文件，也不会在保存配置时访问官网。

存储目录必须存在，可在“浏览”对话框中创建新目录。修改成果和归档位置只影响后续文件，不迁移历史文件；字体缓存 `paths.font_cache` 和历史去重状态 `state.file` 仍在原配置位置，以保留既有解码缓存和去重记录。默认 `原始数据`、`采集日志` 工作表及 Sheet1 七列结构保持不变。相对路径以配置文件所在目录的上一级为基准，与命令行采集一致。

### Windows 每日定时采集

以下命令会创建 Windows 任务计划，默认每天 09:00 执行：

```powershell
.\manage_schedule.ps1 -Action Install
```

执行时间、每天次数和任务名称默认读取 `config/default.json` 中的 `schedule.daily_time`、`schedule.daily_count` 与 `schedule.task_name`。也可在安装时覆盖时间或次数；例如改为每天 08:30 起采集2次，并更新已有任务：

```powershell
.\manage_schedule.ps1 -Action Install -DailyAt 08:30 -DailyCount 2 -Force
```

查看状态或删除任务：

```powershell
.\manage_schedule.ps1 -Action Show
.\manage_schedule.ps1 -Action Remove
```

任务以当前 Windows 用户的有限权限运行，不保存密码，因此执行时该用户必须处于登录状态（锁屏可以，注销不可以），电脑需要开机且能联网。安装时检查电脑时区为北京时间；首次执行安排在下一个指定时刻，安装不会立即触发采集。错过计划时间后，任务会在系统可用时尽快补跑；同一任务正在运行时不会启动第二个实例，单次最长运行 30 分钟。每次计划运行结束后会显示一个自动关闭的状态说明弹窗，默认 15 秒后关闭；弹窗只展示批次、记录数量、输出文件和错误摘要，完整信息仍以日志为准。每次计划运行的控制台输出保存在配置的归档目录下 `scheduler/scheduled_YYYYMMDD_HHMMSS_进程号.log`，详细数据与质量日志仍按批次保存在归档目录中。若只修改配置中的时间，需再次运行安装命令并加 `-Force` 才会更新已注册的任务。

安装时只读验证配置和模板，注册前不会请求官网。更新时间需要显式加 `-Force`；即使加了 `-Force`，也拒绝覆盖或删除其他应用的同名任务。任务退出码沿用采集模块，Windows 任务计划中的 `LastTaskResult` 为 `0` 表示成功或重复跳过；`267011`（`0x41303`）表示任务尚未执行。

离线重放已保存响应时，应使用独立输出、归档和状态路径，避免影响正式历史状态：

```powershell
.\.venv\Scripts\python.exe -m bijie_hydro.cli --config path/to/replay.json collect --input-json path/to/raw_response.json
```

带动态字体标签的历史响应需要对应字体已经存在于配置的字体缓存目录。

## 配置说明

`config/default.json` 的关键设置：

- `source`：页面地址、超时、尝试次数和请求标识。
- `paths`：模板、成果、归档和字体缓存目录。
- `filter.province_names`：贵州省在官网行政区划字段中的允许写法。
- `filter.match_mode`：必须为 `province`。
- `quality`：全国记录数、观测时效、日变幅和历史水位变化阈值。
- `state.file`：贵州省范围专用的上次成功状态文件。
- `output.file_name`：贵州省成果文件名模板。
- `schedule.daily_time`：Windows 定时任务起始执行时间，24 小时制 `HH:mm`。
- `schedule.daily_count`：每天均匀安排的采集次数，整数1..24，旧配置省略时按1次处理。
- `schedule.task_name`：Windows 任务计划程序中的任务名称。
- `schedule.popup_enabled`：是否在定时运行结束后显示状态说明弹窗，默认 `true`。
- `schedule.popup_timeout_seconds`：弹窗自动关闭时间，范围 1..120 秒，默认 15 秒。
- `upload.enabled`：MVP 必须为 `false`。

配置中出现 `city_names`、`allowlist_file` 或 `require_allowlist_match` 会被拒绝，以避免旧版毕节白名单配置继续生效。

## 输出与归档

成功成果写入：

```text
D:/生态/获取/成果/YYYYMMDD/贵州省大型水库实时水情_YYYYMMDD_批次编号.xlsx
```

成果包含：

- `Sheet1`：全部贵州目标记录，严格保持原模板七列结构。
- `原始数据`：当次全国响应、解码值、贵州筛选状态和缺测原因。
- `采集日志`：任务状态、全国记录数、贵州记录数、接口信息和质量检查。

每批归档位于 `D:/生态/获取/归档/YYYYMMDD/批次编号/`，主要文件包括：

- `source_page.html` 和 `raw_response.json`：公开来源原文。
- `font_*.ttf` 和 `decoded_records.json`：字体及解码证据。
- `region_filter.json`：本批实际使用的省级筛选规则。
- `provenance.json`：采集时间、模板校验和、处理版本和回放标识。
- `parsed_records.json` 和 `selected_records.json`：全国解析记录与贵州选中记录。
- `quality_checks.json`、`batch_log.json` 和 `manifest.json`：检查、状态和文件校验和。

模板和成果均采用保护性写入：模板只读，成果先写临时文件并重读验证，已有同名成果拒绝覆盖。

## 状态与质量控制

任务状态包括：成功、重复跳过、无匹配数据、待复核和失败。

- 官网和接口成功、全国结构正常，但没有任何贵州行政区划记录：`无匹配数据`。
- 页面不可达、接口业务状态异常、字段结构变化或贵州记录字体解码失败：`失败`。
- 历史站点消失、观测时间回退或水位变化超过阈值：`待复核`。
- 与上次成功快照完全一致：`重复跳过`，不重复生成成果。

质量检查覆盖全国记录数、字段结构和类型、动态字体、贵州记录数、重复记录、库名与行政区划、观测时间、数值有效性、日变幅、历史覆盖和历史水位变化。非贵州记录的未解析生僻字只记录警告；行政区划无法解码，或已确认属于贵州的记录存在必需字段解码错误时阻断输出。

去重优先使用官网 `idNo`；没有站号时使用“行政区划 + 库名”作为稳定键，避免省级范围内不同地区的同名水库互相覆盖。每个稳定键只保留最新观测。

## 定时与合规

默认每日北京时间 09:00 执行一次，时间可配置；建议先连续人工核验至少三个采集日。单请求默认超时 15 秒、最多尝试两次。403、401 和 429 等访问限制不会短间隔重试。模块不识别验证码，不绕过登录、访问控制或频率限制，只请求公开页面及其同源接口。

退出码：0 表示成功或重复跳过；2 表示采集、质量或配置失败；3 表示本地文件错误；4 表示来源正常但无贵州匹配记录；5 表示访问被拒绝或限流。

生产使用必须保留来源 URL、采集时间和批次归档。官网公开不等于可以无限共享；对外提供数据应遵守已有授权范围。数据结果不能承诺绝对准确或绝对不会泄露，上线前及运行期间仍需人工抽样核验。

## 上传边界

`upload.py` 仅定义 `upload_file(file_path, metadata)`、`upload_records(records, metadata)` 和 `check_upload_status(task_id)`。禁用实现始终拒绝上传，采集流程不会调用上传模块。

后续上传任务应与采集解耦，以目标资料库、目录、文件 SHA-256 组成幂等键。上传失败不回滚已经完成的采集和归档。接入 Seafile 时需另行配置服务器地址、凭证、资料库 ID、目录、文件名、标签和权限，凭证不得写入 Excel、普通配置或日志。
